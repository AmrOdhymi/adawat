# خارطة طريق التطوير

> هذه خارطة مقترحة للمراحل بعد المرحلة صفر. لا تبدأ أي مرحلة قبل موافقة المستخدم الصريحة.
> القاعدة: **مرحلة واحدة نشطة في كل مرة**، ثم تقرير وتوقف إلزامي.

---

## 0. بروتوكول التعاون المعتمد

بناءً على توجيه المستخدم:

**قبل كل مرحلة:**

1. أعرض نطاق المرحلة، وخطة التعديلات، والملفات المتوقعة، والأسئلة الخاصة بها.
2. يراجع المستخدم الخطة ويضيف تعديلات أو يجيب عن الأسئلة.
3. لا يبدأ التنفيذ إلا بإشارة صريحة مثل: «ابدأ».

**أثناء المرحلة:**

- يُنفَّذ نطاق المرحلة المعتمد فقط.
- لا Build / لا تشغيل / لا اختبار واجهة.
- أي اكتشاف يغيّر النطاق جوهرياً يُعرض قبل المتابعة.

**بعد المرحلة:**

1. تقرير بما تم، والملفات، وما تغيّر ولماذا.
2. ما يجب على المستخدم بناؤه واختباره خطوة بخطوة.
3. تحديث `DEVELOPMENT_STATUS.md` و`CHANGELOG.md` و`TEST_REPORT.md`.
4. توقف كامل.
5. المستخدم إما يوافق على الانتقال أو يبلغ بالمشاكل؛ تُصلح المشاكل داخل المرحلة نفسها.

## 1. مبادئ الترتيب

1. **الاستقرار أولاً:** إصلاح دورة حياة النوافذ قبل أي ميزة تفتح نوافذ جديدة.
2. **الأساس المشترك قبل التكرار:** الثيم والعارض والقوائم المشتركة تُبنى قبل الميزات التي تستخدمها.
3. **لا إعادة بناء لما يعمل:** تحسين الحافظة/المفكرة/الإعدادات بدل استبدالها.
4. **الأسهل والمعزول قبل المعماري:** الإصلاحات الموضعية أولاً، ثم الميزات متعددة الوحدات، ثم التغييرات العريضة.
5. **الاعتمادية تحكم الترتيب:** لا تُنفَّذ مهمة بسيطة قبل البنية التي تعتمد عليها.
6. **لا تصميم قبل اختيار:** خمسة تصاميم ثم توقف، ثم اعتماد.
7. **كل مرحلة تُسلَّم مع اختبار مستخدم:** لا يُدّعى نجاح تشغيلي.

### المرحلة 4 — عارض النصوص وPDF (أصلي، بلا محرك ويب) 🟡 نُفِّذت بالدفعات A–E + تحديث 2026-11-26

> **تغيير نطاق (2026-11-22):** أُلغي «محرك عرض المستندات» المعتمد على WebView2/Markdig→HTML. السبب: المستخدم يريد أن تُعرض النصوص منسّقة بدل رموز خام، مع سحب الملفات وفتحها — دون محرك ويب أو أصول خارجية.
>
> **تكملة النطاق (2026-11-25):** أُضيفت خمس دفعات: A تجميد الشاشة أثناء اللقطة، B إصلاح استعادة النوافذ المصغّرة، C فصل معاينة الحافظة/المفكرة عن عارض بعجلتين متعدد التبويبات مع حفظها، D عارض صفحات PDF بحد ذاكرة 256MB، E قارئ LaTeX موسّع.
>
> **تحديث 2026-11-26:** تمرير PDF أسرع (تأخير مسح + رسم أقل + بحث ثنائي للصفحة)، زر Open واحد حسب سياق العارض، وطبقة نص PDF للتحديد/النسخ/البحث داخل العارض دون WebView2 أو حزم جديدة.

**المتطلبات:** F-01، F-02، F-03، F-04، F-05، F-06، F-09، F-10، F-11.

**ما نُفِّذ:**

1. **معاينة بسيطة:** `MarkdownViewer` يعرض ما هو أمام الحافظة أو المفكرة فقط: Markdown/نص منسّق، LaTeX، تكبير، RTL/LTR، نسخ، تصدير — بلا زر Open وبلا استقبال ملفات أخرى.
2. **عارض متعدد التبويبات:** `DocumentViewer` يُفتح من عجلة Alt ومن عجلة Ctrl+Space ومن `action.open`: تبويب لكل ملف، زر Open، سحب وإفلات، إغلاق تبويب، `Ctrl+W/Tab/O`، وحفظ المسارات والترتيب والتبويب النشط ونسبة التمرير والتكبير في `%APPDATA%\Adawat\preview-tabs.json` (20 تبويباً)؛ التبويبات لا تُمحى عند إغلاق النافذة.
3. **Markdown وLaTeX:** GFM كامل عبر Markdig AST → `FlowDocument`، و`TexFlow` يقرأ أقسام LaTeX وقوائمه واقتباساته وكوده وجداوله وصوره وروابطه وحواشيه ونظرياته وتنسيقه ورموزه، مع `MathText` للرياضيات. الأمر المجهول يبقى بنص وسيطه.
4. **الصيغ:** `.md/.markdown/.txt/.html/.htm/.rtf/.docx/.doc/.odt/.epub` عبر `DocumentOps` و`DocFlow`، إضافة إلى `.tex/.latex` و`.pdf`.
5. **PDF:** `PdfView` يرسم الصفحات الظاهرة فقط عند الطلب، ويحتفظ بها في LRU بحد 256MB، ويحفظ المسار ونسبة التمرير؛ التبويبات غير النشطة تُفرَّغ، والنسخ/التصدير معطّلان لصفحات PDF. مع شريط «Page» و`Ctrl+G`، وزرّي Fit/Page، وتنقل PageUp/PageDown/Home/End، زر Open in app، ورسالة واضحة للملف المحمي، وطبقة نص للتحديد/النسخ/البحث (لملفات PDF النصية).
6. **اللقطة:** الشاشة تتجمّد لحظة الالتقاط داخل أداة القص، فلا تتغير الصورة تحت مؤشر التحديد.
7. **النوافذ:** استعادة النوافذ المصغّرة من شريط المهام تعمل عبر `WindowLifecycle.BringToFront`، مع بقاء الإغلاق التلقائي ودورة حياة Phase 1.
8. **أمان:** لا JavaScript ولا WebView2 ولا شبكة؛ الصور تُقرأ من مجلد المستند فقط، وأي مسار يخرج منه يُرفض.

**الصعوبة:** مرتفعة (العارض والتبويبات وPDF).

**الاعتماديات:** المرحلة 3 (رموز الثيم)، `PDFtoImage` الموجود مسبقاً في Core.

**المخاطر:**

- دقة LaTeX محدودة بطبيعتها: تحويل إلى عناصر مستند وUnicode، وليس تنضيداً حقيقياً.
- أداء الملفات الكبيرة داخل `FlowDocument`.
- PDF عالي الدقة يستهلك ذاكرة؛ الحد 256MB مع LRU يقيّد ذلك لكن التكبير المتكرر يعيد الرسم.
- صيغ تحتاج محولاً خارجياً (`.doc`) قد تفشل إن لم يكن Word مثبتاً، فتُعرض رسالة خطأ واضحة.
